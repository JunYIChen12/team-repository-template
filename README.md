# 团队仓库协作规范

本仓库是团队仓库管理与协作规范的唯一权威来源（Single Source of Truth）。它不存放具体项目的业务代码，主要用于统一新项目的协作方式，并为项目仓库提供可复制的 GitHub 模板。

当前规范版本：`v1.0.0`

## 第一次加入团队

按以下顺序开始：

1. 阅读[新人接入指南](docs/ONBOARDING.md)，完成第一次协作演练。
2. 阅读[贡献指南](CONTRIBUTING.md)，了解日常提交步骤。
3. 遇到争议或特殊情况时，查询[仓库管理与协作总规范](docs/REPOSITORY_GOVERNANCE.md)。

## 最重要的六条规则

1. `main` 始终保持可交付，不直接向 `main` 推送代码。
2. 一项任务使用一个短期分支和一个 Pull Request（PR）。
3. PR 必须说明“为什么改、改了什么、如何验证”。
4. 至少一名非作者成员完成审查后才能合并；关键改动需要代码负责人批准。
5. 自动检查失败、审查意见未解决或存在已知高风险时不得合并。
6. 默认使用 Squash Merge，合并后删除短期分支。

## 其他项目如何使用本仓库

本仓库更新后，不会自动覆盖已经创建的项目仓库。团队采用两种方式：

- 规则正文：项目 README 直接链接到本仓库，始终阅读中心最新版。
- 必须存在于项目内的文件：例如 PR 模板、Issue 模板和 CI 配置，通过独立 PR 有控制地同步。

详细步骤和可复制文本见[项目采用指南](docs/ADOPTION_GUIDE.md)。

## 如何修改本规范

规范不是口头约定。任何实质性修改都应先创建 Issue 说明问题，再通过 PR 修改，并同步更新 `CHANGELOG.md`。重大不兼容变化应发布新的主版本，不能无提示地改变所有项目的工作方式。
