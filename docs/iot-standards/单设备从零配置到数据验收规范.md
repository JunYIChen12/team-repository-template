# 单设备从零配置到数据验收规范

版本：`v2.0.0`

## 1. 目的

本规范把[目标驱动的开发、运行与验收规范](../DEVELOPMENT_READINESS.md)应用到 IoT 单设备接入。它定义设备接入的责任边界和验收原则，不把所有层级强制排成一次串行流程。

每次任务先定义目标。例如：完成设备 UI 配置、验证隔离报文接入、验证历史查询，或验证重启恢复。未参与该目标的层标为后置或不适用，不得阻塞当前验收。

## 2. 强制边界

- 平台侧配置必须通过正式 UI 完成。UI 无法执行时，后台操作只能作为经批准的受控例外，并记录 UI 缺口 Issue。
- PLC 只允许 FC01/FC03 只读。禁止写 PLC。
- 不猜测凭据，不向生产 MQTT 发布，不复用稳定环境数据库、Broker 或 Secret。
- 测试消息、设备、Topic、数据库、网络、容器、卷和日志必须任务级隔离。
- `healthy`、数据库存在记录、API 返回成功和静态 Flow 检查不能替代 UI 或端到端验收。

## 3. 八层责任地图

| 层 | 名称 | 主要责任 |
| --- | --- | --- |
| L1 | 资源与配置管理 | 设备、网关、点位、物模型、Topic、版本和启用状态。 |
| L2 | 设备接入与采集任务 | 协议、轮询、连接、超时、重试和采集任务。 |
| L3 | 可靠采集与数据质量 | 时间、重复、乱序、缺失、延迟、补传和质量。 |
| L4 | 数据存储与查询 | 原始值、标准值、latest/history、分页和时间范围。 |
| L5 | 数据处理、事件与计算 | 单位、事件、窗口、累计差值和计算版本。 |
| L6 | 业务上下文关联 | 工单、批次、产品、工序和业务事件关联。 |
| L7 | 北向数据服务 | REST、MQTT、确认、重试、去重、限流和契约。 |
| L8 | 平台治理、安全与运维 | 健康、审计、权限、Secret、备份、恢复和回滚。 |

责任分类使用 `PLATFORM`、`NODERED`、`OPERATION`、`ENVIRONMENT`、`EXTERNAL` 或 `JOINT`。八层用于定位责任和选择证据，不表示必须依次通过 L1 到 L8。

## 4. 选择最小交付路径

### 4.1 仅配置验收

目标是验证设备、网关、物模型或规则的 UI 能力时，只需要：版本与隔离边界、相关 UI 配置、权限回读和 UI 验收。采集器、Broker、真实设备和历史数据均为后置。

### 4.2 报文接入验收

目标是验证一条隔离属性报文时，需要：输入契约、身份和 Topic、隔离采集或测试发送方、平台接收、存储回读和 UI 可见结果。业务计算、北向服务和长期运行只在目标明确需要时加入。

### 4.3 计算或历史验收

目标是验证窗口、事件、历史或计算时，需要：任务级数据库、输入数据、计算定义和版本、运行记录、结果回读和 UI 验收。真实 PLC 或 Node-RED 不是默认前置条件。

### 4.4 恢复验收

目标是验证恢复时，需要：已验收的最小运行组合、Secret 引用、持久化路径、停止/启动入口和 UI 回读。不得用容器重启成功代替业务恢复。

## 5. 每次执行的最小顺序

1. 定义目标、非目标、用户验收入口和适用层。
2. 读取实际启动入口、Flow、Compose、迁移和配置链，选定唯一主线。
3. 一次性记录任务级版本、资源、端口、数据、Secret 引用和回滚边界。
4. 只启动实现目标所需的最小服务和采集组合。
5. 通过 UI 完成配置和验收；日志、API 和数据库只用于诊断或准备隔离数据。
6. 按目标需要验证历史、计算或恢复，并收束临时资源。

数据库迁移、bootstrap、业务配置写入、Secret 导入或轮换、服务重启、流量切换和回滚必须串行并回读。点表阅读、静态 Flow 审查、Issue 分类和测试设计可以并行。

## 6. 输入、消息和证据

输入契约必须明确设备稳定编码、字段、类型、单位、时间语义、质量语义和缺失策略。未知字段、未知设备或非法时间不得靠经验补齐。

消息接入按以下信号逐段观察：采集输入或隔离测试数据、标准化报文、认证与授权、规则命中、物模型校验、存储与计算、正式 UI 回读。每一段只证明自己的事实。

每个任务记录：完整 Git SHA、运行清单、输入契约版本、实际命令、隔离环境、实际结果、证据等级、责任分类、回滚和未覆盖范围。Secret 只记录引用、权限、所有者和撤销方式。

## 7. 常见阻塞处理

| 现象 | 首先确认 | 不允许的替代 |
| --- | --- | --- |
| UI 缺少配置入口 | UI 能力和权限 | 用后台写入宣称 UI 已通过。 |
| Topic 或设备不匹配 | 输入契约、身份和规则 | 自动猜测或创建临时设备。 |
| 消息未入库 | 认证、规则、模型和时间 | 只看 Broker 连接状态。 |
| 数据库有值但页面无值 | 查询、权限、时间范围和 UI 状态 | 用数据库记录替代 UI PASS。 |
| Node-RED 不可用 | 采集层与现场依赖 | 修改平台配置掩盖采集问题。 |

无法解除的阻塞必须记录缺失条件、责任方和最小下一步。未覆盖的设备、版本、性能或生产环境保持明确的 `BLOCKED` 或 `NOT_VERIFIED`。
