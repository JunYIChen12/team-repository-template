# IoT 项目专用规范

本目录是本仓库中的 IoT 项目规范专区。它补充团队通用协作规范，专门约束 IoT 项目的目录、测试、环境隔离、运行资源和验收方式。

## 适用范围

- IoT 平台、设备接入、采集层、物模型、计算、验收和本地运行环境；
- 使用本团队仓库协作规范的 IoT 项目；
- Codex、环境线程、UI 线程、手册线程和采集层专家的任务执行。

## 规则边界

团队通用规则继续由仓库根目录的协作规范负责，包括 Issue、Pull Request、commit、分支和合并流程。本目录不重复定义这些规则。

IoT 项目还必须遵守跨项目 Codex 操作准则；该准则作为机器和工作区级前置规则维护，不在本目录复制。

规则优先级为：用户明确指令 > 团队通用规则 > 跨项目操作准则 > 本目录 IoT 规则 > 项目专用规则。发生冲突时必须停止并报告，不得自行放宽规则。

## 项目采用方式

IoT 项目在自己的 README 或项目规则入口中声明采用的 IoT 规范包版本，并链接到本目录。每个测试任务和验收结果必须记录：

- IoT 规范包版本；
- 本规范仓库完整 Git SHA；
- 项目 Git、Compose、镜像和环境编码；
- 设备、证据和回滚引用。

中心规范更新后，项目通过 PR 评估并同步，不静默覆盖项目自己的规则或运行配置。

候选运行环境的交付步骤只以[候选环境交付契约](候选环境交付契约.md)为流程入口；本目录其他文件分别提供目录、测试、隔离和故障归因的基础规则，不再各自维护候选启动顺序。

故障发生时，先按[故障排查规范](故障排查规范.md)定位边界，再按测试体系记录结论；不要把运行健康、采集持续或后台现象直接写成业务闭环通过。

## 明确不纳入

本目录不保存密码、Token、证书、数据库、业务数据、Node-RED 凭据、运行日志或验收截图。这些内容按项目自己的八层目录和受控存储规则管理。
