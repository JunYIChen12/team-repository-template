# 候选环境交付契约

## 1. 契约身份

- 契约编号：`IOT-CANDIDATE-DELIVERY-001`
- 文档版本：`V1.0`
- 状态：候选环境唯一交付入口
- 适用对象：IoT 候选测试环境；不适用于 accepted、生产或稳定运行环境。
- 目标：把候选版本从冻结、依赖和镜像准备推进到 UI 验收、回滚和交接，并让每一步可复核、可停止。

本文是候选环境的交付流程，不重新定义八层能力。八层名称、职责和能力验收仍以《测试体系核心规则》为准；本契约只规定环境如何承载这些能力。

### 1.1 优先级和状态

- 候选环境必须有独立环境编码、worktree、Compose 项目、网络、Volume、数据库、EMQX、日志目录和任务级 Secret。
- 任一步骤缺少版本、资源 owner、凭据来源、回滚点或外部输入时，状态为 `BLOCKED`，不得用历史记录补齐。
- `NOT_READY` 表示尚未通过启动门禁；`READY` 只表示候选可进入下一阶段，不表示业务验收通过。
- 业务数据迁移、运行基线切换和稳定环境流量切换均须另行审批，不属于本契约的自动动作。

## 2. 八层职责边界

| 层 | 名称 | 候选环境中的边界 |
|---|---|---|
| L1 | 资源与配置 | 记录设备、网关、物模型、Topic、计算定义等配置身份；不以环境文件替代 UI 配置。 |
| L2 | 设备接入与采集 | 设备和采集任务的接入契约；Node-RED/PLC 属于外部采集层。 |
| L3 | 可靠采集与数据质量 | 记录接收、去重、乱序、缺失、过期和质量结果；不把采集器故障写成平台能力。 |
| L4 | 数据存储与查询 | 保存原始值、标准值、质量、来源和查询结果；数据库资源必须候选隔离。 |
| L5 | 数据处理、事件与计算 | 统一计算、窗口、结果、版本和运行记录；后台操作不能替代 UI 验收。 |
| L6 | 业务上下文关联 | 设备、批次、工单和业务事件的关联；输入不完整时保持未知。 |
| L7 | 北向数据服务 | REST/MQTT 等对外读取或投递；消费者和凭据必须候选隔离。 |
| L8 | 治理、安全与运维 | 身份、Secret、审计、健康、备份、回滚、证据和资源清理。 |

Node-RED 只负责外部采集、解码、标准化和上报。它不得写 PLC、发布测试 MQTT 或代替平台 UI/计算/北向验收。

## 3. 不可变候选规则

1. 候选使用单一 Compose 入口；禁止临时 Overlay、手工 `docker run`、未登记的替代网络或第二套运行目录。
2. 版本总账绑定 Git 分支和完整 SHA、worktree、Compose SHA-256、镜像完整 digest、迁移账本、业务配置、Node-RED Flow、证据目录和回滚点。
3. 共享依赖缓存只能作为只读种子；候选必须使用候选任务级可写缓存。不得把完整 `node_modules` 跨项目链接。
4. 依赖安装只允许一次 `bun install --frozen-lockfile`。安装前固定 Bun 版本、registry 选择、lockfile SHA 和缓存指纹；失败即停止。
5. 应用、数据库、EMQX、Node-RED 和证据均使用候选资源。候选不得连接稳定数据库、稳定 EMQX 或生产设备。
6. 镜像必须按已核实的完整 digest 固定；tag 只能作为人类可读说明，不能代替 digest。
7. Secret 只能通过受控 Secret 文件、环境注入或 Secret 管理入口提供。普通配置、日志、Issue、截图和证据不得出现密钥值。
8. 所有迁移、seed、凭据轮换、服务重启、流量切换和回滚均须记录目标、影响、回读和批准角色。

## 4. 阶段交付表

每个阶段均须记录：前提输入、唯一 owner、允许动作、产物/版本指纹、验收信号、`BLOCKED` 条件、回滚/保留策略和交接字段。下表中的 owner 是责任边界，不是自动授权。

### 阶段 0：版本与资源门禁

- 前提输入：候选 Git SHA、任务分支/worktree、环境编码、项目目录、Compose 路径、磁盘和端口预算。
- 唯一 owner：环境负责人。
- 允许动作：只读盘点 Git、worktree、进程、Docker 资源、端口、磁盘和挂载；建立候选 manifest。
- 产物/指纹：manifest、Git 完整 SHA、worktree 绝对路径、Compose SHA、环境/证据目录。
- 验收信号：稳定环境未被候选占用；候选资源 owner、清理边界和回滚路径可回读。
- `BLOCKED`：SHA、路径、owner、端口、磁盘、Docker 状态或稳定资源隔离不明。
- 回滚/保留：不创建运行资源；保留原始状态收据。
- 交接字段：`gitSha/worktree/envCode/composeSha/owner/evidenceDir/rollbackRef`。

### 阶段 1：输入契约

- 前提输入：设备稳定键、控制器/IP/端口/站号/协议、点位地址、功能码、偏移、数量、类型、字序、缩放、单位、枚举和采样周期。
- 唯一 owner：业务配置负责人。
- 允许动作：读取点表和业务确认；登记缺失字段，不得猜测。
- 产物/指纹：点表文件 SHA、输入契约版本、设备和点位清单。
- 验收信号：每个点位均能说明来源、类型和单位，歧义有负责人和截止条件。
- `BLOCKED`：单位、类型、地址、设备身份或业务含义冲突。
- 回滚/保留：保留原点表和冲突记录，不覆盖已登记契约。
- 交接字段：`deviceCode/pointId/sourceSha/type/unit/address/period/unknowns`。

### 阶段 2：设备类型与物模型

- 前提输入：阶段 1 输入契约和稳定设备键。
- 唯一 owner：UI/平台配置负责人。
- 允许动作：通过 UI 创建或回读设备类型、属性、事件、必填/可选、启用和累计清零语义。
- 产物/指纹：UI 回读截图或结构化回执、配置版本、对象 ID。
- 验收信号：属性名称、标识符、类型、单位和状态与输入契约一致；布尔属性无错误单位。
- `BLOCKED`：只能后台写入、UI 无法回读、字段契约不一致或配置覆盖稳定对象。
- 回滚/保留：只回滚候选对象；保留 UI 前后回读，不删除稳定历史。
- 交接字段：`deviceTypeId/identifier/name/dataType/unit/required/status/configRevision`。

### 阶段 3：网关与身份

- 前提输入：网关稳定键、owner、ACL 范围、受控 Secret 来源和过期策略。
- 唯一 owner：安全/环境负责人。
- 允许动作：在候选范围生成、导入或注入任务级凭据；只记录引用、哈希、owner、ACL 和生命周期。
- 产物/指纹：Secret 引用、文件权限/ACL、非敏感哈希、创建/过期/撤销时间。
- 验收信号：候选客户端能以最小权限认证；任何回执不含密钥值。
- `BLOCKED`：Secret 来源、ACL、过期/撤销入口或候选隔离未证明。
- 回滚/保留：撤销候选 Secret，保留稳定 Secret 不动；不复制 EMQX 整个数据目录。
- 交接字段：`gatewayCode/secretRef/owner/aclRef/hash/issuedAt/expiresAt/revokeRef`。

### 阶段 4：Topic 与消息规则

- 前提输入：阶段 1-3 结果和平台 Topic 模板。
- 唯一 owner：平台配置负责人。
- 允许动作：通过 UI 建立候选 Topic/规则，先 dry-run 回读再启用；登记 payload、消息 ID、事件时间、QoS、重试和绑定。
- 产物/指纹：规则对象 ID、模板版本、payload 契约 SHA、启用回执。
- 验收信号：Topic、设备绑定、字段类型和必填字段可回读；唯一约束不影响其他候选设备。
- `BLOCKED`：Topic 模式、消息结构、凭据或唯一约束未确认。
- 回滚/保留：禁用候选规则；不删除仍被历史结果引用的规则或输出。
- 交接字段：`topicRuleId/topicTemplate/payloadSchema/messageId/timeField/qos/retry/consumerScope`。

### 阶段 5：设备与绑定

- 前提输入：设备、网关、物模型和 Topic 对象均已回读。
- 唯一 owner：UI/平台配置负责人。
- 允许动作：UI 完成设备注册、网关绑定、Topic 绑定和启用状态回读。
- 产物/指纹：设备对象 ID、绑定关系、配置 revision、UI 回读证据。
- 验收信号：候选设备只绑定候选网关和规则；稳定设备和历史配置不变。
- `BLOCKED`：对象归属、绑定关系或启用状态无法从 UI 证明。
- 回滚/保留：解除候选绑定；保留历史对象和审计记录。
- 交接字段：`deviceCode/deviceId/gatewayCode/topicRuleId/bindingRevision/enabled`。

### 阶段 6：Node-RED 采集层前置

- 前提输入：已批准的点表、采集文档、Flow 来源/版本/SHA、tab 清单、凭据引用和外部设备可用性。
- 唯一 owner：采集层负责人。
- 允许动作：只读核对 Flow、节点、FC01/FC03、周期、解码、标准化、Topic 和单台重载方案；设备可用时再执行采集验收。
- 产物/指纹：Flow/manifest SHA、tab/节点清单、采集器版本、外部设备前置回执。
- 验收信号：Flow 来源与运行登记一致；采集层不写 PLC、不发测试 MQTT。
- `BLOCKED`：Flow 漂移、设备离线、凭据未注入、协议/地址缺失或责任边界不清。
- 回滚/保留：恢复采集层原登记版本；平台候选对象不因采集失败被删除。
- 交接字段：`flowSha/manifestSha/tab/node/protocol/address/period/credentialRef/deviceReachability`。

### 阶段 7：报文与首次接入

- 前提输入：阶段 1-6 已放行、单台设备、候选 Broker 和平台接收规则。
- 唯一 owner：平台接入负责人。
- 允许动作：先做单台认证/授权预检，再允许一条受控入站消息；不得连接稳定 Broker 或生产设备。
- 产物/指纹：脱敏报文摘要、消息 ID、事件时间、设备/网关、规则匹配和接收回执。
- 验收信号：类型、单位、时间和消息身份一致；接收结果可由平台入口观察。
- `BLOCKED`：消息结构、Topic、Secret、设备绑定或 Broker 隔离未证明。
- 回滚/保留：禁用候选规则并撤销任务凭据；保留失败回执。
- 交接字段：`messageId/deviceCode/topic/eventTime/receivedAt/ruleId/acceptCode/traceRef`。

### 阶段 8：平台接收可观察性

- 前提输入：阶段 7 的受控消息和平台可观察入口。
- 唯一 owner：平台运行负责人。
- 允许动作：只读查看接收成功、拒绝、失败、来源、时间、规则、错误码和 trace；必要时执行已批准的最小重试。
- 产物/指纹：接收日志摘要、错误码、trace、数据库写入计数和时间范围。
- 验收信号：成功/拒绝/失败均可区分，原始值、标准值和质量状态可追溯。
- `BLOCKED`：无合法会话、日志缺字段、无法区分采集/平台责任或数据边界不明。
- 回滚/保留：停止候选流量；保留日志和数据库快照，不清理未知证据。
- 交接字段：`traceId/ingestStatus/errorCode/source/eventTime/receivedAt/rawId/historyId/quality`。

### 阶段 9：UI-only 验收

- 前提输入：阶段 8 有可观察接收结果和合法 UI 会话。
- 唯一 owner：UI 验收负责人。
- 允许动作：只通过 UI 查看对象、启用状态、最新值、刷新、新鲜度、历史、质量、计算运行和配置回读。
- 产物/指纹：截图或结构化 UI 回执，绑定版本、环境和设备编码。
- 验收信号：陌生人员可从页面完成配置回读并解释业务结果；后台/API 只能辅助定位，不能替代 UI PASS。
- `BLOCKED`：UI 无入口、会话失效、页面与 API 版本不一致或只能依赖后台旁路。
- 回滚/保留：不因 UI 失败删除已接收数据；记录 UI 缺口并转平台/UI Issue。
- 交接字段：`page/url/device/object/latest/history/quality/status/uiResult/evidenceRef`。

### 阶段 10：历史与追溯

- 前提输入：阶段 8-9 的数据和计算/规则版本。
- 唯一 owner：数据/计算负责人。
- 允许动作：UI 优先核对原始值、标准值、窗口、质量、来源、输入摘要、规则版本和 revision。
- 产物/指纹：历史查询回执、结果 revision、输入摘要、规则/计算版本。
- 验收信号：固定窗口结果能关联设备、点位、时间、版本和质量；单位/空值语义可解释。
- `BLOCKED`：只有数字无来源、输入清单为空、单位冲突或需要猜测后台数据。
- 回滚/保留：历史结果和输入摘要保留；禁止删除被引用的旧版本。
- 交接字段：`windowStart/windowEnd/value/unit/quality/reason/source/revision/inputManifest/ruleVersion`。

### 阶段 11：重启与恢复

- 前提输入：阶段 0-10 已收据化，镜像、迁移、Secret、Compose 和数据目录已绑定。
- 唯一 owner：环境负责人。
- 允许动作：按固定 Compose 和门禁执行候选重启；仅切换候选镜像或配置，不触碰稳定资源。
- 产物/指纹：启动前后服务状态、迁移账本、镜像 digest、Secret 引用、Node-RED 持久化目录和恢复时间。
- 验收信号：候选在目标时间内达到 API/DB/Broker/业务就绪；数据时间推进，UI 可回读；健康不等于业务验收。
- `BLOCKED`：Secret 未注入、迁移不一致、端口冲突、磁盘不足、恢复路径不明或稳定资源被占用。
- 回滚/保留：停止候选并恢复上一个候选 digest/Compose/Secret 引用；不回滚或删除稳定数据库。
- 交接字段：`before/after/imageDigest/migrationLedger/secretRef/composeSha/readyAt/recoveryRef`。

### 阶段 12：证据、问题与收束

- 前提输入：各阶段回执和未完成项。
- 唯一 owner：交付协调人。
- 允许动作：汇总事实、未知、阻塞、风险、下一步和 Issue/复测条件；标注责任为平台、环境、采集层、操作或外部。
- 产物/指纹：结构化收据、证据索引、完整 SHA、环境编码、设备编码、保留/清理清单。
- 验收信号：每个结论可由陌生人员按路径或索引复核；未验证不写成完成。
- `BLOCKED`：证据缺失、版本混用、秘密泄露、owner 不明或未获迁移/切换批准。
- 回滚/保留：保留源码、业务数据、Secret、当前配置和未完成证据；只清理已确认可重建或废弃资源。
- 交接字段：`receiptId/gitSha/envCode/deviceCode/status/owner/evidenceRefs/blockers/risks/next/rollbackRef`。

## 5. 串行与并行

必须串行：版本门禁 → 依赖 → 镜像 → Secret → 候选空库与迁移 → UI 配置 → Node-RED/采集前置 → 首次接入 → 平台接收 → UI 验收 → 历史追溯 → 重启恢复 → 收束。业务配置写入、Secret 导入、迁移、重启、流量切换和回滚不得并发。

可并行的只读准备：Git/Compose/镜像/端口/磁盘检查，点表和业务输入整理，Flow 静态检查，证据模板准备。并行结果必须在阶段 0 manifest 中汇总后才能放行。

## 6. 数据迁移与基线切换

候选默认使用空库。若确需保留少量脱敏验收样本，必须先做一致性 dump/快照并记录 SHA、owner、范围、恢复路径和批准人。禁止直接复制正在使用的 PostgreSQL 目录，禁止整目录复制含凭据/ACL 的 EMQX 数据，禁止用 seed 冒充业务迁移。

真实业务数据迁移、稳定数据库连接、EMQX 状态复制、代码/镜像基线切换和稳定环境流量切换均是独立审批事项。未完成 schema/迁移兼容、Secret/配置兼容、备份和回滚演练前，候选不得接入稳定资源；候选失败不得改写稳定资源。

## 7. 候选 manifest 最小字段

```yaml
contractVersion: IOT-CANDIDATE-DELIVERY-001@V1.0
envCode: <候选环境编码>
git:
  branch: <任务分支>
  sha: <完整Git SHA>
  worktree: <绝对路径>
compose:
  path: <Compose绝对路径>
  sha256: <Compose SHA-256>
images:
  - name: <镜像名>
    digest: <完整digest>
dependencies:
  bunVersion: <固定版本>
  registry: <已批准来源>
  lockfileSha256: <bun.lock SHA-256>
  cacheSeed: <只读缓存引用>
  taskCache: <候选可写缓存路径>
secrets:
  - ref: <候选Secret引用>
    owner: <owner>
    acl: <ACL引用>
    expiresAt: <时间>
data:
  database: <候选数据库标识>
  emqx: <候选Broker标识>
  migrationLedger: <账本引用>
evidence:
  dir: <证据目录>
  rollbackRef: <回滚记录>
```

尖括号内容是占位符，不是可提交的真实凭据。manifest 中只保存引用、指纹和路径，不保存密码、Token、证书或私密连接串。

## 8. 证据等级与停止线

- 静态检查：代码、文档、Compose、schema 或脚本存在；不能单独证明运行成功。
- 隔离运行：候选空库/隔离 Broker 的可观察运行结果；不能证明稳定环境或生产行为。
- UI PASS：在合法会话下页面完成配置或结果验收；后台/API/数据库只能作为辅助证据。
- 真实环境验收：现场设备、真实数据和业务结果均已观察；必须绑定完整版本、环境和设备证据。

出现以下任一情况立即 `BLOCKED`：候选连接稳定资源、秘密值进入普通文本、版本或 Flow 漂移、依赖重复安装、迁移无备份、端口/磁盘不安全、UI-only 被后台旁路替代、把 Node-RED/操作/外部问题写成平台缺陷，或无法确定证据归属。
