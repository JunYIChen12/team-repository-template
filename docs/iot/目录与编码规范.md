# 星联达 IoT 项目目录与编码规范

版本：v1.0  
生效日期：2026-08-13  
适用范围：`D:\003_workspace`、`D:\codex-artifacts` 及本地 IoT 测试环境

## 1. 核心原则

1. 代码、运行环境、业务数据、采集配置、数据库和验收证据分开存放。
2. 目录名称使用中文，机器需要解析的稳定键使用英文、数字和短横线。
3. 一个版本必须能追溯到 Git SHA、Compose SHA、镜像 digest、数据库迁移版本和证据目录。
4. 同一资源只能有一个明确归属。归属不明的内容不移动、不删除。
5. 目录移动或清理前，必须确认 Git worktree、Docker 挂载、进程占用和恢复路径。
6. 密码、Token、证书和私密连接串不出现在目录名、普通清单、日志或证据中。

## 2. 顶层目录

主目录固定为：`D:\003_workspace`

```text
D:\003_workspace
├─ 00_项目总账
├─ 01_代码仓库
├─ 02_运行时环境
├─ 03_业务数据
├─ 04_采集层_NodeRED
├─ 05_数据库与持久化
├─ 06_证据与验收
├─ 07_备份与回滚
└─ 08_临时缓存
```

`D:\codex-artifacts` 是历史兼容入口。新证据优先放入 `06_证据与验收`；未完成归属核对前，不批量搬迁旧证据。

## 3. 通用编码格式

### 3.1 版本编码

```text
主线类型_版本标识_日期
```

示例：

```text
main_2251859f_20260813
候选_5574eda5_20260806
回滚_712f61cc_20260804
```

规则：

- Git 使用完整 SHA；目录名可使用前 8 位短 SHA，但总账必须记录完整 SHA。
- 日期统一 `YYYYMMDD`，例如 `20260813`。
- `main`、`候选`、`回滚` 表示用途，不表示验收通过。
- 只有带有 accepted 证据和标签的版本，才能登记为可回滚基线。

### 3.2 环境编码

```text
环境类型_版本编码_用途_日期
```

示例：

```text
本地_main_2251859f_测试_20260813
本地_候选_5574eda5_测试_20260806
本地_回滚_712f61cc_验收_20260804
```

环境编码必须和 Compose、网络、容器、Volume、日志前缀一致。默认端口不能被两套环境同时占用。

### 3.3 设备编码

业务设备统一使用：

```text
PLC-102
PLC-105
PLC-106
PLC-107
```

目录中的中文名称可作为说明，但设备编码是稳定业务键，不随显示名称变化。

### 3.4 证据编码

```text
日期_版本短SHA_里程碑_证据类型
```

示例：

```text
20260813_2251859f_M3_迁移验证.json
20260813_2251859f_M5_UI回归.png
20260813_2251859f_环境门禁.json
```

证据文件必须能回指同一份版本总账；截图、日志和 JSON 收据不要只用随机文件名。

## 4. 各目录使用规则

### 4.1 `00_项目总账`

只放项目索引、版本绑定和决策记录：

```text
项目目录与编码规范.md
版本总账_当前.xlsx
环境总账_当前.md
里程碑状态_当前.md
资源归属清单_当前.md
```

版本总账至少包含：Git 完整 SHA、分支或标签、worktree、Compose 文件 SHA、镜像 digest、迁移版本、运行目录、业务配置目录、证据目录和回滚路径。

### 4.2 `01_代码仓库`

只放 Git worktree，不放数据库、日志、Node-RED flow 或运行时上传文件：

```text
当前版本_main_2251859f_20260813
测试版本_候选_5574eda5_20260806
回滚版本_accepted_712f61cc_20260804
```

删除 worktree 前必须先执行 Git 注册核对，并保留未提交修改和 accepted 历史。

### 4.3 `02_运行时环境`

每套环境独立存放 Compose、非敏感配置指纹、日志和运行清单：

```text
本地_main_2251859f_测试_20260813
├─ 编排配置
├─ 服务日志
├─ 运行清单
└─ 端口网络
```

数据库文件、Node-RED flow 和凭据不直接复制进代码目录；通过清单引用它们的独立路径。

### 4.4 `03_业务数据`

存放平台 UI 配置或脱敏导出：

```text
设备配置\20260813_main_2251859f
物模型配置\20260813_main_2251859f
Topic规则\20260813_main_2251859f
计算定义\20260813_main_2251859f
业务配置清单_20260813.json
```

禁止保存数据库 ID、用户密码、MQTT 密码和生产密钥作为普通配置备份。

### 4.5 `04_采集层_NodeRED`

按环境和设备分开：

```text
本地测试_20260813
├─ PLC-102_本地_flow.json
├─ PLC-105_本地_flow.json
├─ PLC-106_本地_flow.json
└─ PLC-107_本地_flow.json
云端部署_20260813
├─ PLC-102_云端_flow.json
└─ ...
```

本地与云端 flow 不混放。凭据使用独立的受控存储，flow 文件中不得写入明文密码。

### 4.6 `05_数据库与持久化`

```text
测试数据库_main_2251859f_20260813
迁移验证数据库_main_2251859f_20260813
业务数据库_历史_20260806
```

数据库目录必须记录 owner、用途、来源、端口、迁移账本和清理条件。未经备份与恢复验证，不删除业务数据库。

### 4.7 `06_证据与验收`

```text
20260813_main_2251859f
├─ M0_基线
├─ M1_环境门禁
├─ M3_迁移验证
├─ M4_服务健康
├─ M5_UI验收
└─ 收束回执
```

证据必须包含输入、动作、结果、证据路径、阻塞、剩余风险和下一步。证据不因年龄自动删除。

### 4.8 `07_备份与回滚`

```text
数据库备份\20260813_main_2251859f
配置备份\20260813_main_2251859f
回滚清单\accepted_712f61cc_20260804
```

备份目录必须注明恢复方式和验证时间。只有确认备份可恢复，才可清理旧运行数据。

### 4.9 `08_临时缓存`

只放可重建内容：依赖缓存、临时数据库、一次性脚本和中间输出。每个临时目录必须带日期和 owner：

```text
迁移临时库_20260813_M3
构建缓存_20260813_main
```

任务结束后，确认无进程、无挂载、无证据价值，才可删除。

## 5. 版本总账最小字段

```text
记录编号：20260813-main-2251859f
Git：origin/main / 完整 SHA
代码目录：绝对路径
Compose：绝对路径 / SHA-256
镜像：名称 / 完整 digest
数据库：绝对路径 / owner / 迁移账本
业务配置：设备、物模型、Topic、计算定义目录
Node-RED：环境目录 / flow 清单
证据：验收目录
回滚：accepted 标签 / 备份路径
状态：规划中 / 验证中 / 可运行 / 已验收 / 已回滚
```

## 6. 清理规则

- `保留`：源码、未提交修改、业务数据、凭据、当前配置、accepted 证据、活动运行资源。
- `可重建`：依赖缓存、构建缓存、临时数据库和中间文件；确认无使用后再删。
- `可删除`：明确废弃且停止、无挂载、无 Git 登记、无业务/回滚价值的空目录或临时资源。
- `未知`：归属、恢复路径或用途不明确；必须保留并记录。

禁止使用 `git clean`、`git reset --hard`、全局 Docker prune 或未经核验的递归删除。

## 7. 目录迁移顺序

1. 建立版本总账，锁定 Git SHA 和当前运行资源。
2. 只读盘点并标记 Preserve/Rebuildable/Deletable/Unknown。
3. 先迁移可重建缓存和已确认的证据副本。
4. 再迁移代码 worktree、运行时配置、业务数据和数据库。
5. 逐项回读 Docker 挂载、Git worktree、进程和端口。
6. 迁移完成后再清理旧目录，保留回滚窗口。

## 8. 命名禁用项

不得使用以下无法表达归属的名称：

```text
new
test
final
final2
最新
临时
备份
old
copy
```

必须附带用途、版本或日期，例如：

```text
测试版本_main_2251859f_20260813
数据库备份_main_2251859f_20260813
```
